# 質問設計

へきネイターの質問は、結果名や題材をそのまま尋ねるクイズではありません。作品の好み、普段の感覚、行動の選び方、美意識などの間接的・抽象的な手がかりから候補を絞ります。

## 目的

各質問の目的は、一つの性癖を直接確認することではなく、その時点で残っている候補群をできるだけ大きく二分することです。質問選択では現在のposteriorとmatrixを使い、YES/NOの予測が拮抗して情報利得が大きい質問を優先します。

例えば「秩序立った関係に惹かれる？」は、主従、契約、軍人、執事、敬語など複数の候補を横断して分ける潜在軸です。「トマトが好き？」から「トマト好き」を返すような一対一の質問にはしません。

## 文面の原則

- 結果名や固有ジャンルをそのまま答えさせず、別の場面や感覚から推定する。
- 一問は複数の候補にまたがる潜在軸として働かせる。
- YESとNOのどちらも自然に選べる、価値判断の偏りが少ない対比にする。
- 質問文だけで意味が分かるようにし、結果を推測させるヒントや具体例は表示しない。
- 似た質問は、記憶、行動、距離感、美意識など異なる観察可能な角度へ分ける。
- 創作の好みと本人の行動を混在させる場合は、どちらを答える質問か本文で分かるようにする。
- 各質問に `answer_frame` を持たせ、「作品・設定」「人物・関係性」「普段の感覚・行動」のどの視点で答えるか常に表示する。
- 迷う利用者には無理に二択を求めず、「わからない」を使ってもらう。

## 品質確認

文面レビューと実測は分けて扱います。

1. 重複、誘導、二重質問、結果名に直結する表現を公開前に確認する。
2. 公開後はYES/NO比率、未回答率、離脱率、discrimination、候補分割の偏りを確認する。
3. 回答が片側に寄りすぎる質問は、特定結果への直結ではなく対比の公平さを見直す。
4. cold-start質問は十分なfeedbackが集まるまで結論を出さない。ただし、文面上の曖昧さや重複は学習を待たず修正する。

## 公開前のmatrix方針

- 意味をレビューできる質問には、複数結果を横断する初期シグナルだけを付ける。特定の結果名をそのまま正解にするseedは禁止する。
- 意味に沿う広範な候補群を安全に決められない場合は、推測でmatrixを埋めず `learning_scale_neutral: true` のcold-startとして公開する。
- 印のない全候補0.5列は既存データ不備として通常プレイから除外する。cold-startとはみなさない。
- cold-startは1診断1問までで、feedback相当量20かつ初期疑似観測を除くlearned discrimination 0.04以上になった時だけ通常枠へ移る。20以上でも0.015未満ならレビュー待ちとして停止する。

強い結果分散ボーナスは最終表示の多様性を作る別の仕組みです。質問設計と質問選択は、引き続き候補を効率よく絞ることを目的にします。
